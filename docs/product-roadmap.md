## 3. Четыре системы, которые надо построить

### 3.1 Живая героиня (приоритет 1)
Нужен настоящий риг вместо меша: слои (волосы передние/задние, лицо, глаза, веки, рот,
тело, костюм, кресло), параметры (взгляд, дыхание, наклон, эмоция), физика (волосы, грудь,
ткань) и микро-поведение (моргание не по таймеру, а по «настроению»; взгляд в курсор;
дыхание, синхронное с репликой; вздрагивание от громкого доната).

Кандидаты (лицензии проверены по репозиториям):

- **OpenBone** (`UXCentury/open-bone`, MIT) — Spine-подобный риг, физика с инерцией/демпфированием,
  state machines, **официальный рантайм `@openbone/pixi` под PixiJS 8** — совпадает с движком игры.
- **Iki** (`zeikar/iki`, MIT) — WebGL2-рантайм + авто-риггер из слоёв или одной картинки,
  формат `.iki` — обычный JSON. Плюс: модель может собрать агент, без ручного рига.
- **Live2D Cubism** — индустриальный стандарт, но проприетарная лицензия на публикацию.
- **See-through + Stretchy Studio / image2live2d** — разложение одной картинки на 23+ слоя,
  дальше авто-риг. Требует GPU (12–16 ГБ VRAM) — вне этой песочницы, но это путь для продакшена.

Рекомендация: пилот на одной позе в OpenBone (Pixi 8 нативно), с проверкой швов, физики и
мобильной производительности. Если швы не примутся — Iki как второй заход.

### 3.2 Чат, который соблазняет (приоритет 2)
Сейчас чат комментирует. Надо, чтобы он **продавливал действие**:
1. Чат предлагает дерзость из каталога (поза, ракурс, предмет, слово) — с учётом дня,
   костюма и текущей boldness.
2. Идёт «давление»: голоса, донаты, сабы. Шкала `pressure`.
3. Порог пробит → она реагирует по boldness: отказ → смущённое согласие → делает.
4. Пейофф: всплеск зрителей, клип, рост boldness, иногда новый саб-стейдж.
5. Отказ — не пустой ход: он тоже контент (её смущение, чат дразнит, давление растёт).

Это даёт цикл, которого нет у конкурентов: игрок не «тапает по картинке», а управляет
социальным давлением.

### 3.3 Пайплайн ассетов (приоритет 2)
`canon-lock` → генерация → `key_plate.py` (1024×1526 RGBA) → **AI-апскейл** → манифест хешей → гейты.

Апскейлер (нашёл, MIT/Apache):
- **Real-ESRGAN** (`xinntao/Real-ESRGAN`, Apache-2.0) — стандарт де-факто, есть `realesrgan-x4plus-anime`.
- **image-enhance-api** (`kalprajsolutions/image-enhance-api`, MIT) — готовый REST/Docker
  (`POST /enhance`, модели x4plus и x4plus-anime). Локально, без облака.
- **Real-CUGAN** уже в репозитории (`experiments/upscale/realcugan_onnx.py`) — второй кандидат.

Рекомендация: self-host Real-ESRGAN ncnn-vulkan за тонкой REST-обёрткой, `x4plus-anime`
для героини, `x4plus` для фонов. Все генерации проходят обязательно, без исключений.

### 3.4 Контент и канон (постоянно)
Костюм = слот (`CostumeSlot`), а не день. Каждый слот: 4 стадии, лестница сабов, манифест,
анатомия, регион дыхания, якоря лица, гвард гардероба, тесты. Канон — `docs/character-canon.md`
и `docs/canon-lock.md`.

## 4. Порядок работ

| Этап | Содержание | Критерий готовности |
|---|---|---|
| P0 | Риг-пилот: одна поза дня 1, слои, дыхание, взгляд, моргание, физика волос | 60 fps на среднем телефоне, швов не видно, кресло не рвётся |
| P1 | Чат-давление: каталог дерзостей, шкала pressure, ветки отказ/согласие | полный цикл «чат продавил → она сделала → клип» на одном дне |
| P2 | Конвейер ассетов: REST-апскейлер, манифест, гейты в CI | новый костюм от генерации до игры за один прогон |
| P3 | Слот-архитектура: `CostumeSlot`, 7-й слот реально в игре | слот подключается данными, без правок кода |
| P4 | Контент-волна: 3–4 новых костюма, по 4 стадии | каждый прошёл канон-сверку и фан-сервис-оценку |

## 5. Границы

Остаёмся в отгруженном регистре и чуть выше: купальник, корсет, чулки, подвязки, sheer-панели,
мокрый глянец. Без наготы, без обхода фильтров, все персонажи — взрослые. Всё остальное —
на полную: качество рендера, анимация, свет, физика, характер.
